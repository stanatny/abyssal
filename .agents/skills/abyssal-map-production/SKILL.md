# ABYSSAL Map Production

Make the first art delivery suitable for the real game: a recognizable place to explore, feed, and fight in, with reviewable evidence before expensive repetition. Codex owns the integrated result; Kimi owns explicitly assigned art work. This skill does not require a particular delegation tool and can be read directly by either agent.

All code paths below are relative to the repository root. Start with [AGENTS.md](../../../AGENTS.md), [README.md](../../../README.md), the current section of [HANDOFF.md](../../../HANDOFF.md), and the [asset quality standard](../../../docs/asset_quality_standard.md). The current task and current implementation take precedence over superseded historical candidates. Project documents and this brief are English; player text supports both `en` and `zh-CN`; code comments are Chinese.

For an agent without automatic skill discovery, include this instruction in its assignment: `Read .agents/skills/abyssal-map-production/SKILL.md and the filled map brief before editing. Work only in the listed worktree and files.` No private Skill, personal registry, or absolute developer path is needed.

## Establish the production contract

Codex prepares a short brief using [references/map_brief.md](references/map_brief.md), filling the decisions needed for this map rather than sending only a theme or species list. Record assumptions that can be decided within the task; ask only for material unresolved user choices. Internal checkpoints below are working reviews, not additional user approval gates.

- **Identity:** the player experience from surface to nursery, transition, deep landmark, and retreat. Specify architecture/terrain language, materials, palette, light sources, fog, atmosphere, fleet/human activity, and the sound of exploration and danger. Regional identity must survive ordinary follow-camera distance; a new tint or distant backdrop is insufficient.
- **Scale and routes:** world-coordinate extents, depth convention, landmark dimensions relative to juvenile and adult bodies, district distribution, and travel/combat clearances. Define the denominator of any coverage target: district area may include streets and plazas, whereas solid footprints and stacked floors are different measures. For a city, show how inhabited districts occupy the promised area; for other maps, specify the appropriate terrain and landmark distribution. Design horizontal and vertical routes when the concept promises them, including entrances, exits, return paths, and adult turning space.
- **Roster and food:** list new/reused species, biological or fantasy references, measurement convention, feeding role, schooling versus loose residency, depth/region bands, population/group anchors, nutrition sources, respawn, and predator exclusions. Identify which shared assets and sounds should be reused. Counts alone do not establish obtainable food.
- **Cost and evidence:** select comparable accepted assets, target views/devices/quality settings, representative scene budgets, and the evidence each author will supply. Determine costs for repeated instances and the populated scene, not only one model. Record any untested target explicitly.

For each creature, select the existing habitat behavior explicitly: a school profile, a roaming individual, a predator territory, or an independent resident with `residentRadius` and `spawnAnchors`. Region configuration supplies coordinates and population; shared `ecosystem_population.js` and runtime behavior own movement and respawn. Do not turn a species-specific visibility complaint into a map-name branch. In particular, tiny non-schooling residents must not use the hunter path that respawns them outside the player's visible radius. Check actual camera-scale discoverability, a period of normal movement, a real consumed-to-respawn cycle, and region switching; a guide card or model count proves none of those. Use a synthetic future-region species in a new habitat-trait regression to demonstrate reuse without a hardcoded current roster.

Atlantis is a lessons source, not a universal map specification: its roughly two-thirds district coverage, three Krakens, and 390 animals were map-specific decisions. Choose future scale, roster, guardian count, and population from that map's brief and actual play requirements.

## Assign ownership before parallel work

Keep one integration owner. Prefer separate worktrees; explicitly assigned non-overlapping files are the fallback allowed by AGENTS.md. Record the base revision, each worktree/branch, exact allowed files, forbidden shared files, integration method, and who owns preview/build/browser services. Directory-wide ownership is valid only when it truly excludes every other writer.

| Owner | Default responsibility                                                                                                                                                                                                                               |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Codex | Scope and brief; shared region registration, simulation, ecology/balance, localization, UI, audio routing and loading lifecycle; combining deliveries; real-scene, performance, and regression review; current project records.                      |
| Kimi  | Named regional environment/architecture/landmark/fleet/creature modules, assigned animation/material work, provenance and art evidence; scoped corrections in those same files. Music composition can be assigned explicitly with its own interface. |

Before Kimi builds, Codex supplies the actual caller contracts: imports/exports, arguments and return fields, units/axes, model normalization, mouth/contact anchors, terrain sampler, collider shapes/transforms, update inputs, quality controls, and resource ownership/disposal. Inspect current entry points such as `src/atlantis_ocean.js`, `src/atlantis_city.js`, `src/creature_atlantis.js`, `src/creature_ecosystem.js`, and `src/region_ecology.js`; reuse their relevant contracts without copying Atlantis's whole design. Kimi reports a necessary shared change to Codex instead of editing a forbidden file.

Use the existing update loop. Share immutable geometry/materials and decoded audio while keeping instance animation/state independent. Identify resources owned by the map versus retained caches, and provide idempotent cleanup. Do not add private animation loops, per-frame geometry creation, broad disposal of shared assets, or debug exports to the production build.

Kimi returns an unstaged diff and an exact file/evidence inventory; neither delegate independently stages, commits, pushes, replaces services, or touches the main checkout. Codex reviews the diff before integration. Preserve and identify unexpected overlapping changes before continuing integration. Follow only the current user's commit/merge/release authorization; this skill grants none.

## Work in reviewable increments

1. **Playable slice:** establish the scale/layout and one representative finished landmark or terrain section, light/material treatment, route, and creature in the real regional wrapper. Include a populated view and initial cost measurements. A labeled blockout can help planning, but does not fulfill finished art acceptance. Codex checks the regional promise and interfaces while changes are still cheap.
2. **Expand the accepted direction:** fill districts/biomes, architecture variants, vertical passages where promised, creatures, ecology, and music in bounded batches. Inspect representative close, normal-distance, and moving views before repeating a kit across the map. Feed specific defects back with positions, captures, and expected behavior; avoid a generic request to "add detail."
3. **Integrate and verify:** Codex checks the combined populated region, actual gameplay events, map lifecycle, bilingual surfaces, and performance. Revise within existing ownership. Do not defer every integration problem to the end, or treat every artist snapshot as ready for the regular roster.

The artist's gallery demonstrates shape and motion; the owner must also inspect the same assets in the actual ocean. Tests, polygon totals, beautiful concept images, and a successful build do not independently establish a finished map.

## Acceptance in the running game

Apply the detailed requirements in the [asset quality standard](../../../docs/asset_quality_standard.md). For a new map, cover this complete chain; for a narrower revision, select the affected checks and expand only for new failures or risks.

| Area                     | Evidence needed                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Place and scale          | Surface, descent, approach, central landmark, side district/biome, and retreat views under actual lighting/fog. Show recognizable regional identity at normal camera distances and close structural detail. Verify the brief's measured footprint/distribution; a wide screenshot cannot prove scale or exploration depth.                                                                                                                                                                                                                                                     |
| Ground fit and traversal | Sample the final rendered terrain across full support footprints, not just nominal terrain centers. No floating or buried buildings, inward faces, exposed seams, or terrain-pierced floors. Check visible solids against colliders, reserve full overlapping footprints, and move actual bodies both ways through promised routes/levels/wells with the final collider set, including grown bodies, turns, and fast motion. Empty water above a roof is not a traversable interior.                                                                                           |
| Creature quality         | Comparable accepted asset; side/front/rear/three-quarter views, normal scene distance, full motion cycles and transitions. Verify anatomy, attached fins/limbs, species silhouette, material variation, normalization, head/travel axes and visible mouth/capture paths. Guide and world must use the same models. Research real species and qualify extinct reconstruction and fantasy adaptations.                                                                                                                                                                           |
| Ecology and survival     | Safe, nutritious juvenile feeding; continuous medium-to-large feeding layers; legal moving population in intended habitats; actual feeding and normal respawn without wall overlaps or band drift. Audit schools along exploration routes and deeper districts, not only near spawn. Tiny decorative residents cannot substitute for nutritious juvenile schools or adult meals.                                                                                                                                                                                               |
| Music and sound          | Distinct exploration, chase, and lord arrangements through the actual audio graph; appropriate reuse of feeding, voice, warning and ability effects. A warning sound or louder ambience is not combat music. Actual pursuit and engaged-lord states must trigger audible entry and smooth exit; ordinary attack-ability cooldown state is not pursuit state. Dormant/returning lords must not force combat music. Capture and listen to encounter/escape, mixed effects, mute, pause, map switch and restart; record listening status separately from objective signal checks. |
| Integration              | Real region selection changes environment, population, appearance and audio. Check both characters, guide filters independent of expedition selection, `en`/`zh-CN`, launch, pause, Return Home, restart and repeated region switching. If loading changes, verify visible feedback, locked controls, shader readiness and rollback/retry after preparation failures. Preserve other regions' content and behavior.                                                                                                                                                            |
| Performance              | Profile the populated running scene with live AI, collisions and audio in a visible headed browser, plus relevant narrow layouts and both quality presets. Record machine/browser/GPU, resolution, scene/seed, warm-up, sampling, frame-time distribution, CPU costs, draw calls/triangles and resource growth. Use matched before/after conditions and serialize benchmark browsers. Headless rates, mesh-count savings and phone-sized viewports do not establish real-device smoothness.                                                                                    |

Keep hunger and related rules shared. Read [survival_balance.md](../../../docs/survival_balance.md) and the current AGENTS rules; use `hungerDrainRate()`/`HUNGER_RULES` and real nutrition/healing/growth helpers rather than adding regional formulas or changing balance to compensate for sparse food. Evaluate both characters at 3, 6, 10, 16, 25 and 30 m with obtainable meals, travel and battle reserves, and the actual world/display-depth distinction. Preserve current nursery protection, hunger returns from valid lord bites, lord eligibility, victory and active-play limit unless the task explicitly changes them. Label budget models and staged encounters; they do not prove natural whole-round pacing.

For underground or stacked routes, include the actual regional lowest-ground sampler, body clearance and world bounds in traversal tests. Collider-only tests can pass while the game's floor projection prevents descent. Keep roofs and intermediate floors as separate solids; verify a real input-driven descent below the original seabed and a return route, including the follow camera. Check rendered roof triangles as well as collision signatures: a decorative full-width sheet can accidentally cover an intended courtyard, while a real roof slab can lack a collider. Preserve intended openings in both representations.

For hollow land above water, keep land placement and lowest underwater floor as separate samplers, with an actual cap/ceiling and supporting terrain. Cross-check rendered floor/roof heights against movement projection, not only metadata. Traverse each promised connection both ways with the registered grown characters without per-frame teleport corrections. Put actual food in new routes through existing habitat/respawn data; preserve intended profiles and assert total stock independently from accessible nutrition. Sample the complete transformed placement of riverbed plants, shells and rotated stones so decorative detail neither floats nor blocks declared passages. The [Amazon refinement](../../../docs/amazon_refinement.md) is a worked example, not a requirement that every future map have three crossings or its inventory.

## Delivery and useful precedents

Return the source revision/diff inventory, checks actually run, evidence paths and methods, fixed defects, and remaining visual/listening/device/pacing limits. Keep raw captures/logs in ignored `.local/`; store concise conclusions in the current verification record. Codex synchronizes relevant README/HANDOFF, guide, menus, HUD, localization and tests. Run the necessary formatting, focused tests and build; verify that the served preview actually matches the reviewed build. A preview is not a release. Missing essential visual/listening evidence leaves that aspect pending acceptance, without inventing a new approval requirement for routine implementation.

### Underground support checks

For excavated rooms, compare the full transformed footprint of furniture and marine roots with the **rendered** terrain and the shared floor. A valid center sample can hide a chest, tipped jar or bench in an edge slope. Keep the excavation's smoothing band inside the lining thickness, or provide explicit supported placements; do not conceal the error with extra lights. Refine only necessary edge cells and verify triangle-interior error and cost together. Test a grown character's continuous turns at route corners and endpoints, not just point-to-point rays. If a regional factory supports only one registered site, reject other site data explicitly instead of returning geometry inconsistent with its metadata.
