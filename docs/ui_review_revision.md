# Cross-device interface review

**Release follow-up:** The user authorized inclusion in v0.8.0 on October 1. The scope/status below records the earlier review candidate; current release verification and deployment status are in [verification](verification.md).

## Scope and status

This uncommitted follow-up on `feature/mariana` preserves the responsive-loading and idle-rendering candidate at the pushed `3292104` baseline. The user asked for an overall UI review while accepting that performance candidate. No new commit, push, main integration or Pages release is authorized. The published build remains v0.7.2.

Review covers the four regions, both playable characters, English and Simplified Chinese, keyboard and touch presentation, portrait/landscape phones, tablets and short laptop windows. Gameplay, ecological populations, nutrition, progression, collisions, audio and model quality are unchanged.

## Findings and changes

- **Pause and results:** Phone pause screens previously offered keyboard-only instructions. Short landscape screens could push Return to Home below the viewport, and the secondary action had a small hit area. A scrollable content area now sits above a fixed action row with two reachable 48 px buttons. Background radar, alerts and touch controls are visually suppressed while the dialog is open and restored on resume, without hiding their runtime state. Length, elapsed active time, prey eaten and defeated lords have a consistent statistics layout. Pause shows the current regional task; expandable help explains the actual character skill, cooldown and regional objective using the appropriate touch or keyboard instructions.
- **State-specific copy:** Pause explicitly says survival and skill timers are frozen. The header action changes to Continue during pause and disappears on terminal results. Victory explains the selected regional ending; timeout no longer assumes every map uses the same growth ending. Existing Continue, Dive Again and Return to Home behavior is preserved.
- **Active-play header:** The already-disabled language selector and edition text are hidden during an expedition, leaving room for usable quality, sound and pause controls. Language selection returns on the home screen. Touch header actions and disclosure/filter controls have at least 44 px target height.
- **Selection and keyboard browsing:** Reopening a destination chooser brings its selected item into the panel's visible area. Keyboard changes in the Ocean Guide keep the selected archive row inside its own list. Neither operation scrolls the whole page or the independent model/details pane. Escape and focus restoration remain intact.
- **Missing HUD breakpoints:** Tablet mission/radar, pursuit warnings and bottom controls now occupy separate regions. Short laptop windows use a compact mission/radar stack. Narrow phone landscape uses a dedicated layout instead of inheriting the portrait overview grid; survival bars, skills and alerts no longer overlap. Lower-priority notification text yields space when a lord warning is present, without changing warning triggers or hiding the lord/pursuit information.
- **Landscape Ocean Guide:** The regional selector moves into the title row. The search and species list retain usable height; smaller landscape phones use independently scrollable list and detail columns. Guide themes still follow the system, with its model cache and single rendering loop unchanged.

## Verification and evidence

Raw captures and reports are kept in ignored `.local/ui_overall_review/`. The initial audit captured 60 home/Guide/play/pause/death screens across four regions and four viewport families. The native interaction matrix passed all 32 region/character/view combinations at 1440×900, 1024×600, 768×1024, 390×667, 320×568, 844×390, 667×375 and 568×320. English is exercised on desktop and multiple narrow layouts; all four regions and both characters are exercised in Chinese on 390×667. Representative light and dark Guide states are captured. After fitting the landscape specimen preview to the available height, all eight affected landscape combinations passed again. A further 16 desktop/portrait cases passed after suppressing background HUD panels during pause/results, including restoration on resume. The screenshots are retained alongside their reports.

The matrix uses actual menu selection, Guide keyboard navigation, skill activation, pause/help, focus trapping, Escape, restart and home actions. It checks selected-row visibility, horizontal overflow, reachable action targets, touch bar alignment, correct device instructions, localization and frozen pause time. Death, timeout and regional completion are deliberately staged through runtime state to isolate result presentation; these captures do not establish natural full-round success or balance.

A separate nine-viewport pressure scan places pursuit, lord, ink, notification and buff panels together to measure layout bounds. Its final AABB checks report no overlaps for the measured panel/control rectangles. This is a synthetic simultaneous-layout check, not evidence of a naturally occurring combat encounter. Screenshots were visually inspected alongside the native interaction cases.

Fresh checks include 23 focused localization/Guide/objective unit tests, all 29 shared browser checks, formatting and build. All seven lifecycle groups also passed: four-region idle/time/resize/quality/resume checks, preparation rollback, warmed repeated-switch resource stability and WebGL context restoration. The production preview is rebuilt from the candidate: 172 runtime source fingerprints match, all eight artifacts match both local and public responses, and all eight four-region desktop/touch interaction cases passed. The public build exposes no development game API; source, Git metadata and internal documentation paths remain denied. One initial byte-check request timed out, and the first touch navigation waiting for the browser load event also timed out; subsequent byte matching and application-ready interaction checks succeeded. These transient network observations are kept separately from UI failures. The lifecycle script now waits for the actual pause/resize redraw before measuring idle frames; fixed 80/100 ms sleeps could previously count that required redraw as an idle frame. Its animated-state check establishes repeated rendering rather than assuming a particular FPS on the test host. The earlier performance comparison remains in [the preparation revision](performance_preparation_revision.md); this UI review does not establish a further active-play FPS or thermal improvement.
